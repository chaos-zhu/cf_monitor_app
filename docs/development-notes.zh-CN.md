# CF Monitor 历史开发记录

> 本文保留宣传素材整理前的实现说明与验收记录。项目介绍、运行方式、MIT 许可及最新素材以 [英文 README](../README.md) 或 [中文 README](../README.zh-CN.md) 为准。下文的“本次约定”和测试数量均指当时的开发阶段。

CF-Server-Monitor 的 Flutter iOS / Android 客户端，首期版本 0.1.0。

## 已实现

- 页面流程：站点列表、添加／登录、单站点首页、服务器详情、新增服务器。
- 多站点添加／编辑／删除；站点和 JWT 独立存储，密码不落盘。
- 可设定或取消默认主页站点，下次启动直接进入该站点；系统后退和 iOS 右滑返回站点管理页。
- 公开访问与普通账号密码登录；JWT 过期后重新登录。
- 条形图服务器列表、分组、地区筛选、在线统计、速度／流量／剩余价值。
- 服务器列表“+”右侧可切换卡片／紧凑列表布局，选择保存在本机，跨站点及重启后保留。
- 登录后可新增服务器，填写名称与分组，成功后展示可复制的探针安装命令并刷新当前站点列表。
- 安装页支持输入或下拉选择 GitHub 代理；长按服务器卡片可删除或重新查看安装命令。
- 资源、网络、系统信息，历史范围 10M～7D，图例开关、触摸采样。
- 可选 GPU、磁盘 IO、线路延迟与丢包；缺失、禁用与真实零值分别处理。
- 当前站点 WebSocket 订阅、心跳、重连、断线轮询、前后台恢复；遵守站点连接时限。
- 中英文界面；主题可跟随系统或固定明亮／暗黑，偏好保存在本机；安全区域与可滚动布局。

仅支持 HTTPS（可信证书），允许端口与反代路径前缀。填写最终地址，接口重定向不会转发登录凭据。
首期不实现 Turnstile：全局验证站点提示不支持，登录验证站点不提交密码；公开站点仅有登录验证时仍可匿名查看。超过 24 小时历史按服务端要求登录。

不包含站点设置、其他后台管理、跨站点聚合、推送、小组件及其他首页视图。

## 环境与运行

开发基线：Flutter 3.44.1 stable / Dart 3.12.1；iOS 最低版本为 15.0。依赖版本记录在 `pubspec.lock`。

```sh
flutter pub get
flutter run
```

Android 应用 ID：`dev.cfmonitor.cf_monitor_app`；iOS Bundle ID 相同。iOS 真机需在 Xcode 中选择自己的签名团队。安全存储插件使用 CocoaPods；首次 iOS 运行需要可用的 CocoaPods 环境。

## 自动验证

```sh
flutter analyze
flutter test
```

2026-11-04 本次执行结果：`flutter analyze --no-pub` 无问题，`flutter test --no-pub` 全部 92 项通过。

测试不访问真实站点，使用内存存储、模拟 REST 传输及 WebSocket 流，覆盖单位与计费规则、认证隔离、增量乱序、迟到快照、连接释放、连接时限、权限与四页导航，以及 320 宽深色／1.5 倍字体布局。历史回归覆盖两分钟完整上报与秒级局部样本混合、缺失字段和真实断点、长范围采样间隔，以及线路窗口末值与平均丢包率。

`10M` 表示查看最近十分钟；完整历史点密度由服务端采集、上报和存储策略决定。与 Web 一致，仅此范围叠加实时样本；长范围按站点的 `long_history_points` 设置判断采样间隔。列表线路延迟使用历史窗口末个有效值，丢包率使用窗口有效值的平均数；窗口无数据时回退到单次上报值。

首页汇总网速与 Web 一样每秒统一更新一次，取当前在线服务器的最新速度总和，避免多台服务器连续推送造成频繁跳动；下拉刷新与恢复前台读取快照后立即更新。时序测试覆盖密集推送、零速、离线排除及暂停恢复。

站点的“…”菜单可设为默认主页站点；每次启动只自动尝试进入一次，返回管理页后不会再次跳转。私有站点复用有效凭据，凭据过期时打开登录页；无法连接时停留在管理页提示原因。删除默认站点会清除默认选择。测试覆盖偏好持久化、启动导航、系统后退、iOS 右滑、取消和删除，以及失效凭据和连接失败。

点击站点立即进入列表页面，在页面内统一完成凭据、配置检查与首次列表加载，不再先在站点卡片等待或展示整页空白 loading。服务器数据返回即展示，本机摘要保存和 WebSocket 握手不阻塞列表。正常握手期间不显示快照提示；实时通道失败时展示数据更新时间与下拉刷新提示，连接成功后移除。实时订阅建立后仍在后台核对一次列表，补齐 REST 请求与订阅之间的更新。回归覆盖慢请求、加载中返回、初次加载时禁用下拉刷新，以及握手失败与重连过程。

列表页顶部使用 18 号站点名和紧邻的状态圆点，地址保持单行；长名称省略时保留圆点和右侧“+”入口。“+”进入新增服务器页，未登录或凭据失效先登录当前站点；取消登录返回列表。新增接口与 Web 一致，提交服务器名称和可选分组，成功后刷新当前站点，并直接展示“安装探针”页面。默认生成 Linux 命令，可切换 OpenWrt／Alpine／FreeBSD、macOS、Windows、Docker；命令与 Web 使用相同安装来源和默认参数，通过当前站点的管理接口读取安装密钥及自定义 UA，支持一键复制。安装参数仅在本页内存中使用。命令获取失败时仅重试获取，凭据失效可重新登录，不重复创建。测试覆盖登录与取消、凭据撤销、创建接口与凭据隔离、重复提交拦截、草稿保留、命令参数转义与复制，以及窄屏大字体布局。

按本次约定，开发阶段只执行 Flutter 分析和测试，不执行 Android/iOS 构建、模拟器或真机验证。原生签名、安全存储插件实际行为、真实 Worker／网络兼容性及指标与 Web 的逐项对照由使用者真机验收。

安装页在目标系统下提供 GitHub 代理输入框和预设下拉菜单，默认直连；代理同时用于安装脚本地址和安装器的 `--install-ghproxy` 参数，Docker 镜像不使用该代理。创建后以及返回服务器列表时，使用管理接口 `list` 的 `refresh: true` 读取最新名单，补齐新增、移除已删除记录，避免 Worker 的列表缓存延迟。长按卡片可打开“删除／安装命令”菜单；操作需要登录当前站点，删除前二次确认，失败时保留卡片，登录失效可重新登录。已有服务器的安装命令使用原服务器 ID，不重复创建服务器。测试覆盖代理选择与手输、非法地址、返回强制刷新、长按安装、删除取消／失败／成功、凭据失效重登及站点隔离。

布局切换入口位于服务器列表页“+”右侧，初始保持卡片布局。两种布局共用相同的顶部汇总、站点信息和地区筛选，切换仅改变服务器卡片。紧凑列表中每台服务器使用独立圆角面板，面板之间保留 10 像素间隔；每行展示名称与彩色 IP 标识、在线状态、系统和运行时间、首项负载、三列资源条、底部网络信息：三条线路、下载和上传五项等宽排列，名称在上、数值在下；资源标签靠左、数值靠右，网络区域上方以浅色细线分隔。最多展示三条线路，长名称及网速完整值可长按查看提示。详细信息继续在详情页查看，长按管理和下拉刷新沿用原有流程。切换只改变展示，不触发额外请求或重连。测试覆盖 切换时顶部汇总与筛选位置不变、390×844 含安全区域首屏展示多台服务器、实时指标更新、详情与长按安装入口、跨站点与重启后的布局保存，以及 320 宽深色／1.5 倍字体布局。

站点管理页右上角的设置入口支持中文／English，以及跟随系统／明亮／暗黑主题；默认中文和跟随系统，切换即时应用到所有页面并保存在设备偏好中，重启后恢复。站点与服务器名称、标签、自定义线路名及安装命令保留原文。暗黑模式使用中性的炭黑背景、深灰卡片与灰色边框，绿色用于状态和交互强调；菜单、弹层及对话框也使用中性灰表面。测试覆盖设置持久化与写入失败、重启恢复、系统亮度变化、语言切回、英文列表／详情／安装／连接表单和错误提示，以及 320 宽／1.5 倍字体布局。

## 真机验收建议

1. 添加公开站点和普通登录的私有站点，重启确认站点与登录保留；两个站点使用相同服务器 ID 时仍独立展示。
2. 对照同一站点 Web 首页及详情，检查 CPU、容量单位、月流量、线路、价格／到期及可选 GPU／IO。
3. 切换历史范围、资源／网络／系统页签并触摸图表，确认公开站点长历史会提示登录。
4. 断网恢复、锁屏返回、反复进入详情及切站，检查实时更新与连接状态。
5. 编辑地址确认旧登录被清除，删除站点确认只影响本机；检查 JWT 失效重新登录。
6. 在两端检查键盘、小屏、大字体、横屏、安全区域、浅深色与持续前台性能。
7. 在站点菜单设为默认主页，重启应用确认直达服务器列表；系统后退／右滑应回到管理页，并可取消默认或改选其他站点。
8. 新增服务器后选择或输入 GitHub 代理，核对并复制命令；直接返回列表确认新卡片出现，长按卡片再次打开安装命令，并检查删除取消／确认流程。
9. 点击“+”右侧图标切换列表／卡片，检查首屏密度、资源条和线路延迟；切换站点、重启确认选择保留，并验证列表中的详情、长按菜单与下拉刷新。

10. 在设置页切换中文／English 和三种主题，返回其他页面检查同步效果；重启确认偏好保留，跟随系统时切换系统明暗，确认暗黑背景、卡片和弹层无绿色底色。

500 个订阅 ID 为当前 Worker 限制：首期实时订阅前 500 台，其余通过手动刷新更新。图表只展示真实采样；不补造缺失点，不承诺恢复断线期间的全部实时样本。

## 结构

- `lib/core/`：数据模型、格式化、API、存储、实时会话。
- `lib/features/`：四类页面；添加页复用为编辑与登录。
- `lib/widgets/`：公共视觉组件、条形卡片、原生 CustomPainter 图表。
- `test/`：协议、模型、持久化、会话与页面测试。

四页导航使用 Flutter Navigator，图表使用原生 CustomPainter，以减少首期依赖。
